# Plan: TFL Viewer v3.1 — Review System, Audit Trail & Source Data View

**Date:** 2026-03-18  
**Scope:** Add a review/comment system with role-based audit trail, threaded responses, Excel audit export, and a Source Data tab showing the filtered dataset behind each TFL.

---

## What Is Being Built

Four features layered on top of v3.0:

1. **Source Data Tab** — a new viewer tab that displays the `analysis_data` object captured from each TFL script — the actual filtered dataset that produced the output, not the raw source datasets shown in the Dataset Explorer.
2. **Review Comment System** — reviewers identify themselves (name + role), leave comments on any TFL, and those comments are persisted per TFL as JSON files in `reviews/`. Comments are displayed in the Reviews tab and compiled into an Excel workbook.
3. **Role-Based Audit Trail** — every comment carries a reviewer role (Statistics Lead, Safety Lead, Medical Lead, Programming Lead, Clinical Operations Lead, Other). The audit status bar shows at a glance which roles have reviewed a given TFL. No comment from a role = not reviewed.
4. **Threaded Responses** — reviewers can reply to existing comments. Replies are indented under the parent comment in the UI and linked via `parent_id` in the data model. The Excel export preserves thread structure through a `Thread_ID` column.

## Data Model

### Comment Object (JSON)

```json
{
  "id": "rev-20260318-111000-abc123",
  "tfl_key": "tfl_t14_1_1",
  "reviewer": "Jane Smith",
  "role": "Statistics Lead",
  "timestamp": "2026-03-18T11:10:00",
  "text": "Disposition counts verified against ADSL.",
  "parent_id": null
}
```

- `parent_id = null` → top-level comment
- `parent_id = "<id>"` → threaded response to that comment
- `role` is selected from a fixed list defined in `REVIEWER_ROLES`

### Storage

- One JSON file per TFL in `reviews/` (e.g. `reviews/tfl_t14_1_1.json`)
- Each file is an array of comment objects
- Comments are append-only; new comments are added to the end of the array

## Implementation Steps

### Phase 1 — Review Infrastructure

**Step 1 — Create `R/reviews.R`**

New helper module with these functions:

| Function | Purpose |
|---|---|
| `build_review_id()` | Generate unique comment ID from timestamp + random suffix |
| `load_reviews(tfl_key, reviews_dir)` | Read all comments for a TFL from its JSON file |
| `save_review(tfl_key, comment, reviews_dir)` | Append a comment to the TFL's JSON file |
| `get_tfl_review_status(tfl_key, roles, reviews_dir)` | Named logical vector: which roles have reviewed |
| `get_audit_summary(tfl_registry, roles, reviews_dir)` | Data frame: one row per TFL, one column per role |
| `compile_reviews_excel(tfl_registry, roles, reviews_dir, output_file)` | Two-sheet Excel workbook |

---

**Step 2 — Update `R/runner.R`**

Capture the `analysis_data` object from the TFL script's execution environment. After `source(script_path, local = env)`, check if `analysis_data` exists in `env` and include it in the returned result list. This is the filtered dataset that the script used to produce `tfl_output`.

Added to both the success and error branches of `run_tfl_script()`.

---

**Step 3 — Update `global.R`**

Add:

```r
REVIEWS_DIR <- "reviews"
REVIEWER_ROLES <- c(
  "Statistics Lead", "Safety Lead", "Medical Lead",
  "Programming Lead", "Clinical Operations Lead", "Other"
)
dir.create(REVIEWS_DIR, showWarnings = FALSE, recursive = TRUE)
```

---

### Phase 2 — UI Changes

**Step 4 — Add Source Data tab**

New tab in the TFL Viewer `navset_card_tab`, positioned between Output and Dataset Explorer. Renders `current_tfl()$analysis_data` in a searchable DT table with Excel/CSV export buttons. Shows a fallback info alert if the TFL script does not define `analysis_data`.

**Step 5 — Add Reviews tab**

New tab at the end of the TFL Viewer `navset_card_tab` with these sections:

| Section | Components |
|---|---|
| Reviewer Identity | `textInput` (name) + `selectInput` (role from REVIEWER_ROLES) |
| Audit Status | Dynamic badge bar: green badge per role that has commented, grey for missing |
| Comments | Threaded display: top-level cards with indented reply cards beneath |
| Add Comment | `textAreaInput` + Submit button |
| Reply | Per-comment Reply button → modal with response form |
| Export | Download button for the Excel audit workbook |

**Step 6 — Add Review Status to Registry table**

New "Review Status" column in the Registry DT showing "N/6 reviewed" per TFL. Refreshes when comments are submitted.

---

### Phase 3 — Server Logic

**Step 7 — Source Data display**

- `output$source_data_info_ui` — row/column count header
- `output$source_data_table` — DT table rendering `tfl$analysis_data`

**Step 8 — Comment CRUD**

- `tfl_reviews()` reactive — reads JSON for current TFL, re-reads on `rv$review_trigger` change
- `observeEvent(input$btn_submit_review)` — validates inputs, saves comment, increments trigger
- `observeEvent(input$btn_submit_reply)` — saves reply with `parent_id`, closes modal

**Step 9 — Threading & audit display**

- `output$reviews_list_ui` — renders threaded comment list with role-coloured badges
- `output$audit_status_ui` — per-role badge bar (green check or grey X)
- Reply buttons dynamically observed per comment

**Step 10 — Excel export**

- `output$dl_review_audit` download handler calls `compile_reviews_excel()`
- Sheet 1 "Review Log": one row per comment/response, `Thread_ID` links threads
- Sheet 2 "Audit Summary": one row per TFL, one column per role

## Excel Workbook Structure

### Sheet 1: Review Log

| Column | Description |
|---|---|
| TFL_ID | TFL key (e.g. tfl_t14_1_1) |
| TFL_Name | Human-readable TFL name |
| Thread_ID | Groups parent + replies (= parent's comment ID) |
| Comment_ID | Unique comment identifier |
| Parent_ID | Empty for top-level; parent's ID for responses |
| Type | "Comment" or "Response" |
| Reviewer | Reviewer name |
| Role | Reviewer role |
| Timestamp | ISO timestamp |
| Comment | Comment text |

### Sheet 2: Audit Summary

| Column | Description |
|---|---|
| TFL_ID | TFL key |
| TFL_Name | Human-readable name |
| Statistics Lead | "Reviewer Name (date)" or empty |
| Safety Lead | "Reviewer Name (date)" or empty |
| Medical Lead | "Reviewer Name (date)" or empty |
| Programming Lead | "Reviewer Name (date)" or empty |
| Clinical Operations Lead | "Reviewer Name (date)" or empty |
| Other | "Reviewer Name (date)" or empty |

## Reviewer Roles

| Role | Typical Responsibility |
|---|---|
| Statistics Lead | Verify statistical methods, population counts, p-values |
| Safety Lead | Confirm adverse event coding, MedDRA mapping, safety signals |
| Medical Lead | Clinical interpretation, protocol alignment |
| Programming Lead | Code review, reproducibility, data flow correctness |
| Clinical Operations Lead | Protocol compliance, data collection alignment |
| Other | Ad-hoc review (data management, regulatory, QC) |
